# v0.9.0 Multiplayer Architecture（Trusted Client + Host World Authority）

> 状态：方向已定，Phase 1 代码已落地（fixed-in-code，待真机）；Phase 2+ 按序迁移。
> 原则：客户端负责玩家自身体验与本地原版逻辑；Host 负责世界状态、持久化与最终同步。不再让 Host 代替客户端执行 Darkwood 原版交互。

## 一、Authority 划分

**Client Authority（客户端拥有，Darkwood 原版已实现，不重新实现）**

```
玩家移动 / 玩家动画 / 玩家输入
玩家背包 / 快捷栏 / 拾取物品 / 丢弃物品 / 使用物品
翻窗 / 开门动作 / 玩家交互动画
```

**Host Authority（主机拥有）**

```
世界状态 / 地图状态 / 建筑状态 / 机器状态 / 事件状态
NPC 状态 / 随机事件 / 保存数据 / Entity 生命周期
```

## 二、同步系统拆分（不再一个万能同步系统）

| 系统 | 职责 | 当前对应实现 | 状态 |
|---|---|---|---|
| PlayerSync | 位置/旋转/速度/动画/ActionState/生命/装备，Client→Host→Others，10-20Hz | PlayerPose 中继 | ✅ 已有 |
| InventorySync | 玩家背包/快捷栏快照 + revision 门 | `PlayerInventoryStatePayload{playerId,revision,slots}` | ✅ 已有 |
| EntitySync | 对象存在/生成/销毁/ID 绑定（不含内部状态） | EntityId/Binding/RuntimeEntity Spawn/Despawn | ✅ 已有 |
| WorldStateSync | 世界对象状态（夹子/发电机/灯/机器/事件） | `WorldStateAdapterRegistry` + typed Adapter（Generator/Light/BearTrap/Door） | ✅ 框架已有，adapter 逐步扩充 |
| EventSync | 即时事件（Generator 开 / Trap 触发 / 门打开 / 机器启动 / 剧情事件） | `BroadcastStateNow`（事件即时状态广播） | ✅ 事件通道已有 |
| SnapshotSync | 加入时全量快照 | 世界快照（注册表+Entity 全量） | ✅ 已有 |

## 三、InventorySync（重点，已落地）

- 拾取地面物品：客户端**不模拟 Cursor**——只发 PickupRequest，Host 用真实原版 DroppedItem 数据转移进权威背包（revision++），ack=InventorySnapshot → 客户端原版 createItem 初始化 Icon/Sprite/UI。**拾取直进背包** ✓
- 丢弃：由 Cursor 唯一创建（ownership=CursorOwned），Host 创建真实世界 DroppedItem 并广播 RuntimeEntitySpawn（客户端绝不本地 Instantiate，防 Runtime Ghost）✓
- 数据格式：`InventorySnapshot {playerId, revision, items[]{slot,type,amount}}`；**Revision 门：小 revision 拒绝覆盖、大 revision 接受** ✓
- HeldItem / ContainerGrab 走 Host 事务 + 客户端原版 Replay（`AuthorityReplayScope`）——已真机验证部分，保留

## 四、WorldStateSync

- 统一接口 `IWorldStateAdapter`（CanHandle/SchemaId/Capture/HasChanged/Apply/EnterClientProxyMode/ExitClientProxyMode）≈ `WorldStateManager`
- BearTrapState{armed,triggered,broken} → `BearTrapStateAdapter`（armed=isOn、broken=destroyed、TriggerBlocker 幂等启停）✓
- GeneratorState{running,fuel,powered} → `GeneratorStateAdapter`（fuel 仅 Host drain；客户端只视觉代理）✓
- LightState{enabled,brightness} → `LightStateAdapter`（light.enabled/destLightIntensity/poweringDown/lowPower；不同步 GameObject）✓
- 状态同步原则：**同步 State，不同步 Method Call**（客户端不发 `Generator.turnOn()` 指令链；Host 执行原版后广播状态）✓
- 只同步状态标量，绝不同步 GameObject 引用 ✓

## 五、Shared Container

- 容器属 World State；操作客户端可原地执行（原版 Replay），Host 保存权威 state + revision++ + 广播；多人冲突 Host 解决 ✓（HeldToContainer/ContainerGrab 已按此实现）

## 七、最终形态

Darkwood Multiplayer 不是"一个网络层替代 Darkwood"，而是"让多个 Darkwood 实例共享世界状态的同步框架"：每个 Client 运行完整 Darkwood，Host 维护共同世界，同步 State 而非 Command。

## 本轮落地（v0.9.0 框架重构，fixed in code）

- **目录分层落地**：`World/` → `WorldState/`；新增 `Network/`（PlayerSync/InventorySync/EntitySync/WorldStateSync/EventSync/SnapshotSync 门面）、`Authority/`（ClientAuthority/HostAuthority 门面）；`Replication/` 由 RuntimeEntities 承担（映射记录）。
- **Drop → Trusted Client 原版执行**：客户端允许原版 `spawnDroppedInvItem` 本地执行（生成掉落物）→ Postfix 捕获本地对象 + 上报（Host 扣减权威/分配 EntityId/广播 Spawn）→ 发起者收到 spawn 广播时**本地原版对象复用为 mirror**（`TakePendingLocalDrop` 类型/位置匹配，杜绝双份/ghost）；2.5s 未匹配则销毁本地对象。
- **EventSync：PlayerAction 动作事件**（新 ActionKindWire.PlayerAction + ProtocolMessageType.PlayerAction）：本地已执行的动作 → 事件 → Host Relay → 其他客户端播放（播放钩子扩展点）。注意：Darkwood 无独立 vault 方法，翻窗=窗口交互+位置同步（已由 Door/Window Client Authority + PlayerPose 覆盖）。
- 注：门/窗/物品激活此前已是 Client Authority 模式（本地原版执行 → Postfix 上报 → Host 保存/广播）——本次重构保留并确认。
